1. **본문 생성 시**: LLM이 "2025 최신정보"처럼 과거 연도 + '최신/기준/현재' 조합을 지어냄

## 연도 오류 패턴

```
패턴 1: "2025 최신 정보" / "2025 기준" / "2025 현재"
패턴 2: "2024년 최신 트렌드" / "2023년 기준 가격"
패턴 3: 카드 라벨에 "2025년형" 등
```

## 참고 구현: 스레드 파이프라인 `validate_year()`

- 화이트리스트 방식: 기사 본문 연도 + 현재 연도만 허용
- 그 외 연도는 차단

## 설계 방향: 3겹 방어

1. **입력단 (1차)**: 소스 데이터 보정 — TourAPI/DB 등 소스에서 오는 과거 연도 중 '최신/기준' 문맥만 현재 연도로 치환. **실제 이벤트 날짜(축제 개최일 등 사실 정보)는 절대 변경하지 않음**
2. **생성단 (2차)**: 프롬프트 지시 — LLM에 "근거 없는 연도 금지, '최신/YYYY년 기준' 표현은 현재 연도만 사용" 명시
3. **출력단 (3차)**: 사후 검증/치환 — 최종 본문(md)과 카드 문구 양쪽에 공통 유틸 적용

## 제약

- 코드 수정 금지. 계획(PLAN.md)과 컨텍스트(CONTEXT.md) 산출물만
- 읽기 전용 조사(grep/read)는 허용
- 사실 날짜(축제 개최일, 이벤트 기간 등)는 절대 치환하지 않음
- `20\d{2}\s*(최신|기준|현재)` 패턴은 자동 치환 (글 버리지 않음)
- 카드 문구의 연도는 항상 `datetime.now().year` 기준
