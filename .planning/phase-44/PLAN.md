# Phase 44: 블로그 간 중복 해소 + 역할 분리

**Milestone:** M3 — 9점 품질 달성
**Goal:** 같은 키워드 체인 내3개 블로그 간 콘텐츠 중복을 탐지하고, 각 블로그의 역할이 제대로 분리되었는지 검증.

## Why

AI가 비슷한 키워드로 비슷한 콘텐츠를 생성하는 경향. rotcha(정보) vs issue(비교) vs techpawz(실전) 역할 분리가 제대로 안 되면 독자가3개 글을 순서대로 읽을 이유가 없어짐.

## Plan

### W1: cross_blog_checker.py

- 동일 chain_id의3개 포스트를 비교
- 키워드 오버랩 비율 계산 (TF-IDF 또는 단순 키워드 기반)
- 중복 기준: 동일 키워드50% 이상 오버랩 = 위반

### W2: 역할 분리 강제 규칙

- rotcha: 정보성 섹션(개요, 특징, 기준) 위주 → "비교표", "구매" 금지
- issue.techpawz: 비교/검증 섹션(A vs B, 검증 항목) 위주 → "제품 개요" 단독 금지
- techpawz: 구매/실전 섹션(체크리스트, 가격, 추천) 위주 → "정보 전달" 단독 금지
- 계약서(Phase 41)의 필수/금지 섹션과 연동

### W3: 게이트 통합

- `quality_gate.py`에 중복 검증 추가
- 중복 + 역할 분리 위반을 각각 별도 Violation으로 보고

### W4: pytest

- 역할 분리 정상 케이스 (통과)
- 역할 혼재 케이스 (위반)
- 중복 콘텐츠 케이스 (위반)

## Dependencies

- Phase 41 (contracts/ YAML의 역할 정의)
- Phase 45 (HTML 렌더링 후 비교)

## Risks

- TF-IDF가 한국어에서 제한적 → 키워드 오버랩 기반으로 시작
- 역할 경계가 모호한 카테고리 존재 → 계약서로 명시적 경계 설정
