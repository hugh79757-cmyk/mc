# Phase 29: 블로그 형식/외형 검증 - Research

**Researched:** 2026-07-28
**Domain:** Blog post format/visual structure verification across 3 Hugo sites
**Confidence:** HIGH

## Summary

Phase 29 verifies the format/visual integrity of blog posts generated by the mc system across 3 sites (rotcha.kr → issue.techpawz.com → techpawz.com). The research maps every verification target to its source code implementation, identifies what `_verify_before_deploy()` already checks vs. what remains unverified, and designs the verification script architecture.

The existing `_verify_before_deploy()` (chain_publisher_core.py:149) handles pre-deploy safety checks (JSON residue, HTML comments, featureimage validity, broken images, ad slot count) but does **not** verify: card injection count/placement, cross-link URL correctness, H2 structure matching `stepSections`, frontmatter completeness, or Hugo HTML rendering of thumbnails. The existing `audit/audit_chain.py` checks prompt leaks, markers, CTA leaks, whitelist, and featureimage URL format — but also does not check card injection or H2 structure.

**Primary recommendation:** Create a new `audit/audit_format.py` script that complements the existing audit infrastructure, covering the 10 verification items in CONTEXT.md.

### Card Injection Logic Details

**Bottom card** (`inject_bottom_card`, line 370):
- Looks for `<!--next_link-->` or `<!-- next_link -->` markers first
- Fallback: finds last H2 position, inserts after that H2 section
- Uses `chain-card` shortcode for Depth 0/1, raw HTML for Depth 2

**Mid card** (`inject_mid_card`, line 392):
- Only if H2 count ≥ 3
- Inserts after 2nd H2 section (before 3rd H2)
- Uses same card type as bottom (chain-card for Depth 0/1, external for Depth 2)

**Card count per post:** Maximum 2 (1 mid + 1 bottom). The D9 gate removes existing cards before re-injection to prevent duplicates.

## Common Pitfalls

### Pitfall 1: Flat file vs bundle directory
**What goes wrong:** Checking `content/posts/{slug}.md` instead of `content/posts/{slug}/index.md`
**Why it happens:** Hugo supports both leaf bundles and page bundles; mc uses leaf bundles (slug directory + index.md)
**How to avoid:** Always check `{site_path}/content/posts/{slug}/index.md`

### Pitfall 2: Card count after D9 re-injection
**What goes wrong:** Counting cards before D9 gate strips old ones
**Why it happens:** `inject_cards_into_draft()` starts by removing existing cards (D9 gate)
**How to avoid:** Verify against the **final** published index.md, not draft_md from DB

### Pitfall 3: External link card vs shortcode card
**What goes wrong:** Only looking for `{{< chain-card >}}` shortcode and missing raw HTML external cards
**Why it happens:** Depth 2 uses `build_external_link_card()` which outputs raw `<div>` HTML, not shortcodes
**How to avoid:** Check for both patterns: `{{< chain-card` shortcode AND `<div style="...">` with "관련 공식 사이트" or "더 많은 정보"

### Pitfall 4: Hugo build path for published output
**What goes wrong:** Looking for HTML at `public/posts/{slug}/index.html` when some sites use `public/{slug}/index.html`
**Why it happens:** Permalink patterns differ between sites (rotcha uses `/posts/:slug/`, others use `/:slug/`)
**How to avoid:** Check both paths, or derive from permalink_pattern in chain_config.yaml

### Pitfall 5: featureimage in body vs frontmatter
**What goes wrong:** Searching for featureimage in the body text instead of frontmatter
**Why it happens:** `_ensure_frontmatter()` strips stray featureimage from body (line 563)
**How to avoid:** Parse frontmatter separately, then check featureimage field

## Code Examples

### Parsing frontmatter from index.md
```python
# Source: chain_publisher_core.py patterns
import re
def split_frontmatter(content):
    if content.startswith("---"):
        end = content.find("---", 3)
        if end != -1:
            return content[:end+3], content[end+3:]
    return '', content
```

### Verifying card placement position
```python
# Bottom card: after last H2 section
# Mid card: after 2nd H2 section (when H2 >= 3)
# Check card HTML appears between expected H2 positions
h2_positions = [m.start() for m in re.finditer(r'^##\s', body, re.MULTILINE)]
if len(h2_positions) >= 3:
    # Mid card should be between h2_positions[1] and h2_positions[2]
    mid_card_pos = body.find('{{< chain-card')  # or raw HTML
    assert h2_positions[1] < mid_card_pos < h2_positions[2]
```
